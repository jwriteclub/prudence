# Prudence

Prudence is a Go port of SANY, the parser and semantic checker in the TLA+
tools. You give it the text of a TLA+ module, and it runs SANY's syntax,
semantic and level checks and reports errors with SANY's messages and
positions. It depends only on the Go standard library and needs no Java.
To load other modules, you pass in a resolver, so the library itself never
reads the filesystem.

I wrote it for tools like [spec](https://github.com/jwriteclub/spec) that want SANY's exact behavior inside a Go binary, without also needing to ship a JVM.

On a selection of 9,453 TLA+ modules, prudence agrees with stock SANY on the
9,425 where SANY reaches a verdict. For the 4,106 cases that SANY accepts, prudence
accepts them too. For the cases that SANY rejects, the error count, line
and column number, module and message text are the same. There are 28 cases on which
SANY crashes, and prudence accepts none of them. Prudence is tested against
[sany-conformance](https://github.com/jwriteclub/sany-conformance).

The lexer and parser are generated by jigo from SANY's unmodified grammar,
`tla+.jj` (see [PROVENANCE](PROVENANCE)). Semantic analysis and level checking
are ported from SANY's Java source at TLA+ commit
`dc6a944429fe3e26104d38f9ff792d2d5d83f307`.

## Use

```sh
go get github.com/jwriteclub/prudence
```

Needs Go 1.22 or later. `Check` runs the full check (syntax, semantic analysis
and level checking) on one root module:

```go
src := []byte(`---- MODULE Counter ----
EXTENDS Naturals
VARIABLE x
Init == x = 0
Next == x' = x + 1
====
`)
res, err := prudence.Check(context.Background(), prudence.Request{Path: "Counter.tla", Text: src})
if err != nil {
	log.Fatal(err) // invalid request, cancellation or a resolver failure
}
if res.Completion != prudence.CompletionComplete {
	fmt.Println("no verdict: the check stopped early")
}
for _, d := range res.Diagnostics {
	fmt.Printf("%s:%d:%d: %s: %s\n", d.Path,
		d.Span.Start.Line+1, d.Span.Start.Column+1, d.Code, d.Message)
}
```

`Path` is only used for printing diagnostics. The standard
modules (`Naturals`, `Sequences`, `TLC` and the others) are embedded, so many cases
do not need a resolver. A spec with its own modules sets `Request.Resolve`, and you
must supply the relevant text of the requested file (or indicate that it's not found).
See [Module resolution](docs/api.md#module-resolution).

`Result.Completion` says whether the analysis finished, not whether the spec
is valid: a complete result can contain errors, and an incomplete one means
the answer is unknown. `Parse` runs syntax analysis only, and `Tokens` runs
the lexer only. Neither loads other modules.
